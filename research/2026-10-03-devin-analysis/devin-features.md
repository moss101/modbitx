# Devin Desktop App — Complete Feature Inventory

**Target:** `/Users/mohsin/zee/Devin.app` (macOS) · **Analysis date:** 2026-10-03
**Purpose:** enumerate every user-facing Devin surface that a local Electron AI-assistant clone (chat app + agent loop + tools + artifacts + terminal + browser pane + settings) could reimplement.

**Method:** read `product.json` fully; enumerated `out/vs/sessions/` (dedicated sessions-window bundle, 44 MB) incl. `skills/`; mined `out/nls.messages.json` (21,220 UI strings) + `out/nls.keys.json` (1,797 module→string-key maps, which expose the full feature-module tree); inspected bundled `extensions/`; grepped `out/main.js` for the sessions window entry.

## 3. Top 12 features to port into a local clone (ranked)

1. **Agents Window / inbox with session list** — *Evidence: A1, A2, A7.* The single highest-value surface: a dedicated window whose sidebar lists all sessions with status chips/filters and an inbox welcome screen. *Minimal approach:* Electron app whose main window is a session list + chat split; sessions = SQLite rows (id, title, repo, status, timestamps) driving both list and inbox.

2. **Typed transcript step cards** — *Evidence: B1, B2, B3.* Devin's chat is not bubbles — it's a timeline of typed cards (command+output, file edit, grep/read, browser action, permission decision) that keeps long agent runs readable. *Minimal approach:* event-sourced agent loop emitting a discriminated-union step log; a React component map renders each type with collapse/expand.

3. **Skills: SKILL.md + slash menu + toolbar buttons** — *Evidence: C1, C2, D4.* 12 built-in skills show the pattern: markdown with frontmatter, user-overridable copies, invokable by name, by button, or by agent choice; `fork` subagent execution is a nice differentiator. *Minimal approach:* skills dir scanned at startup → registry; frontmatter name/description surfaced in `/` menu and as quick-action buttons wired to canned prompts.

4. **Permission modes + per-tool approval rules** — *Evidence: D1, D2, D11, D8.* The ask/Autopilot/Bypass dial plus "always allow this command" rule creation at session/workspace/user scope, with password-prompt detection. *Minimal approach:* permission service consulted before each tool call; rules table (pattern → scope); modal offering Once/Session/Always.

5. **Checkpoints** — *Evidence: B4.* Restore workspace and conversation to any past turn. *Minimal approach:* git-stash-style snapshot (or shadow git branch) per user turn + serialized chat log; hover affordance on old messages.

6. **Changes view + inline agent-feedback comments** — *Evidence: E1, E2.* PR-style review of the session's diff with line comments that feed back into the agent (their `act-on-feedback` skill is the model). *Minimal approach:* diff compute (worktree vs base) → multi-file diff viewer; comments stored per session and injected into the next prompt.

7. **Plan editor flow (draft → review → implement)** — *Evidence: F7.* Plan drafting state, editable plan document, explicit accept, then execution. *Minimal approach:* plan as a markdown artifact edited in a dedicated tab; "Implement" switches the agent into execute mode with the plan as system context.

8. **Browser pane with narrated step cards** — *Evidence: F1, F2.* An embedded browser the agent drives, with every action (navigate/click/type/screenshot/console) rendered in the timeline. *Minimal approach:* Electron `<BrowserView>` + CDP driver exposed as tools; log actions to the transcript.

9. **Terminal pane with run commands** — *Evidence: D5, D6, I16.* Session-bound terminal, agent-suggested commands with edit/approve, and `tasks.json` entries flagged `inAgents` in a Run dropdown. *Minimal approach:* node-pty terminal bound to session cwd; `inAgents` task filter; suggest-command UI reusing the approval modal.

10. **Customization hub: instructions, agents, hooks, prompts** — *Evidence: C3, C4, C5, C6, C12.* One tree (user/workspace scopes) of `AGENTS.md`-style instructions, persona files, hook configs, prompt templates — the big lever for making a clone feel power-user-ready. *Minimal approach:* conventional folders (`AGENTS.md`, `.agents/skills/`, hooks.json), a tree view, and a loader that injects them into system context.

11. **Worktree-per-session parallelism + fork** — *Evidence: A3, A9, E9.* Sessions run in isolated git worktrees so multiple agents proceed in parallel; any message forks. *Minimal approach:* `git worktree add` per session with a worktree registry; fork = copy log + worktree ref at step N.

12. **Settings page with Local Customizations tab + ACU-style usage metering** — *Evidence: I1, H2, B13.* A React settings page separate from stock settings, plus per-turn metering (tokens/tool calls/files changed) shown on each step — the honest version of ACU accounting. *Minimal approach:* settings JSON schema → generated UI; usage rows recorded per step and aggregated on a dashboard.

## 4. Notable negatives / non-portable

- **Devin Cloud VM lifecycle** (A4, A5, D12, F3, F6, F12): session machines, sleep/wake, pairing-code local access, computer use, cloud terminal, webapp mount — all require the vendor fleet. A clone can fake the UX against Docker/local VMs.
- **Slack/Teams bot, PR auto-fix/takeover, enterprise blueprints, impersonation, org policy enforcement, marketplace sync** — server-side vendor infrastructure.
- **DeepWiki** — third-party hosted wiki QA (VENDOR).
- **Supercomplete/Tab Jump/code maps** — model-quality dependent (PARTIAL).
